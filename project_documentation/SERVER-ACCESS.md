# Доступ к серверу и развертывание

## Общее

Кодовая база на сервере: `/Fan-vers.com/app/src`

Бэкенд: `/Fan-vers.com/app/src/backend`

Фронтенд: `/Fan-vers.com/app/src/frontend`

Git-remote настроен на GitHub (SSH): `git@github.com:Reergard/FanVers-Django-React.git`.

На сервере ничего не коммитим и не пушим от имени разработчиков. Развёртывание делает админ через `git pull --ff-only`.

## Роли и учётки

- **fanvers.back.freelance** — бэкенд разработчик.
- **fanvers.front.freelance** — фронтенд разработчик.
- **fanvers.support** — саппорт/админ, выполняет синхронизацию с GitHub и обслуживает сервер.

Есть системные владельцы/админы (root и т.п.) — они выдают доступы и перезапускают сервисы.

**Примечание:** на файловой системе используется группа `fanvers-core`. У файлов встречаются ACL (+ в `ls -l`). Доступ выдаётся адресно, по запросу. Если нет прав на запись — не «чините» это сами, пишите саппорту.

## Что где лежит

- **Бэкенд .env (прод)**: `/Fan-vers.com/app/src/backend/.env`
  - В git не попадает (игнорируется).

- **Настройки Django**: `/Fan-vers.com/app/src/backend/FanVers_project/settings.py`.

- **Фронтовый прод-env (Vite)**: временный файл `frontend/.env.production` на сервере не хранится (удалён), для сборки создаётся локально (см. док ниже).

## Политика изменений

Ветка `main` защищена правилами (требуется Pull Request). Рабочий процесс:

1. локально создаёте фиче-ветку от `main`
2. коммитите, пушите ветку на GitHub
3. создаёте Pull Request в `main`
4. после ревью и мержа админ синхронизирует сервер:

```bash
sudo -i
git -C /Fan-vers.com/app/src pull --ff-only
```

На сервере держим чистое рабочее дерево: никаких правок в проде руками.

## Что игнорируется (важно)

- `backend/.env`, любые `.env*` (переменные окружения).
- Билд-артефакты фронта: `frontend/build/`, `frontend/dist/` (и симлинки на них).
- Django статика сборки сервера: `backend/staticfiles/`.
- Логи: `backend/celery.log`.
- Redis дампы: `dump.rdb`, `*.rdb`.

Локальные «рабочие» каталоги на сервере скрыты через `.git/info/exclude`:
- `wt-backend/`, `wt-frontend/`, `frontend/dist` — не трогать.

## Линейки и окончания строк

В репозитории используем LF. На Windows настроить редактор/IDE на LF, чтобы не плодить CRLF.
